# 部署说明（树莓派 Pi 5 + 800×480 触摸屏）

从零装到开机自启的完整步骤。每一步都给出**验证方法**，装完能自己确认对不对。

---

## 0. 装之前先确认这几件事

```bash
# 系统与内核
cat /etc/os-release | head -3
uname -a
# Qt 与 Python
python3 --version                 # 需要 3.9+
# 屏幕分辨率（应该是 800x480）
cat /sys/class/graphics/fb0/virtual_size 2>/dev/null || xrandr | grep '\*'
# 相机设备节点
ls -l /dev/video*
v4l2-ctl --list-devices 2>/dev/null || echo "未安装 v4l-utils（可选）"
```

记下实际的 `/dev/videoN`。这一步的结论要写进配置文件，不要靠"默认 0 号"猜。

## 1. 系统依赖

```bash
sudo apt update
sudo apt install -y \
  python3-pyqt5 python3-pyqt5.qtsvg \
  python3-psutil \
  python3-opencv \
  v4l-utils \
  fonts-noto-cjk
```

| 包 | 作用 | 不装的后果 |
|---|---|---|
| `python3-pyqt5` | 界面 | 起不了图形界面（`--headless` 仍可用） |
| `python3-psutil` | CPU / 内存 / 网卡计数 | 部分遥测字段走 /proc 降级，读不到的标「不可用 + 原因」 |
| `python3-opencv` | V4L2 相机采集与截图 | 相机能力声明为「未接入」，其它功能照常 |
| `v4l-utils` | 确认相机路径与支持格式 | 只能靠猜设备号 |
| `fonts-noto-cjk` | 中文字体 | 界面中文会变成方块 |

> 用 `apt` 装的 PyQt5 与 Python 版本匹配，比 `pip install PyQt5` 稳。
> **本项目没有任何 pip 专有依赖**：WebSocket、HTTP、SQLite、日志轮转全用标准库。

验证：

```bash
python3 -c "from PyQt5 import QtCore; print('Qt', QtCore.QT_VERSION_STR)"
python3 -c "import psutil, cv2; print('psutil', psutil.__version__, '/ cv2', cv2.__version__)"
fc-list :lang=zh | head -3
```

## 2. 部署程序

```bash
sudo mkdir -p /opt/woodpulse
sudo chown -R "$USER":"$USER" /opt/woodpulse
# 把项目内容复制过去（woodpulse/ samples/ tools/ tests/ docs/ 都要）
rsync -a --delete ./ /opt/woodpulse/
cd /opt/woodpulse

# 数据目录（批次产物、数据库、日志）
sudo mkdir -p /var/lib/woodpulse && sudo chown "$USER":"$USER" /var/lib/woodpulse
```

验证样例包（**必须先有样例包，否则响应序列没有数据源**）：

```bash
python3 tools/make_samples.py --verify samples
# 期望：3 个包，通过 3，失败 0；退出码 0
```

如果没生成过：

```bash
python3 tools/make_samples.py --out samples --force
```

## 3. 写配置

```bash
cp /opt/woodpulse/docs/config.example.json /var/lib/woodpulse/config.json
nano /var/lib/woodpulse/config.json
```

最小改动项：

```json
{
  "platform": {
    "platform_url": "http://192.168.1.10:8000",
    "device_id": "handheld-02",
    "device_token": "换成现场分配的令牌",
    "demo_session_id": "demo-01"
  },
  "camera": { "backend": "v4l2", "device": "/dev/video0", "width": 1280, "height": 720, "fps": 15 },
  "ui": { "width": 800, "height": 480, "fullscreen": true },
  "data_dir": "/var/lib/woodpulse"
}
```

也可以用环境变量覆盖（适合 systemd 单元里写）：

```bash
export WOODPULSE_PLATFORM_URL=http://192.168.1.10:8000
export WOODPULSE_DEVICE_ID=handheld-02
export WOODPULSE_DEVICE_TOKEN=xxxx
export WOODPULSE_DATA_DIR=/var/lib/woodpulse
```

优先级：**代码默认值 → JSON 文件 → 环境变量 → 命令行参数**。

配置项写错名字会**直接报错**，不会静默忽略 —— 这是刻意设计的，避免"改了配置没生效"。
配置文件读坏时程序照常启动（退回默认值）并在日志里写明原因，现场不至于开不了机。

验证：

```bash
python3 -m woodpulse --check
```

预检会逐项报告：Python 版本、Qt 绑定、psutil、OpenCV、数据目录可写、
样例包就绪数、SoC 温度接口、可用摄像头、平台可达性。
带「失败」的项会阻断启动并给出退出码 1；「注意」项不阻断。

## 4. 触摸屏与显示

### 4.1 屏幕方向与分辨率

`/boot/firmware/config.txt`（旧系统是 `/boot/config.txt`）：

```ini
# 5 英寸 800x480 常见面板
hdmi_group=2
hdmi_mode=87
hdmi_cvt=800 480 60 6 0 0 0
# 触摸方向不对时，按面板实际方向调整
# display_rotate=0
# lcd_rotate=0
```

改完重启，确认 `xrandr` 里是 800x480。

### 4.2 隐藏鼠标指针与关闭屏保

触摸屏上不需要鼠标指针：

```bash
sudo apt install -y unclutter-xfixes
```

在桌面自启里加 `unclutter -idle 0.5 -root`；或直接用下面的 X 启动方式（无桌面）。

关闭黑屏与 DPMS：

```bash
xset s off; xset -dpms; xset s noblank
```

### 4.3 无桌面直接起 X（推荐，省内存）

触摸屏终端不需要完整桌面。用 `xinit` 直接拉起程序，约 180MB 内存即可：

```bash
sudo apt install -y xinit xserver-xorg xserver-xorg-legacy
sudo dpkg-reconfigure xserver-xorg-legacy    # 选 "Anybody"
```

`~/.xinitrc`：

```bash
#!/bin/sh
xset s off; xset -dpms; xset s noblank
unclutter -idle 0.5 -root &
cd /opt/woodpulse
exec python3 -m woodpulse --fullscreen >> /var/lib/woodpulse/logs/xsession.log 2>&1
```

```bash
chmod +x ~/.xinitrc
startx        # 手工验证
```

### 4.4 触摸校准（电阻屏才需要）

电容屏一般不需要。电阻屏用 `xinput_calibrator`，把结果写成 xorg.conf.d 片段。

## 5. 开机自启（systemd）

无桌面方案：

```ini
# /etc/systemd/system/woodpulse.service
[Unit]
Description=木脉智检手持检测终端
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=pi
WorkingDirectory=/opt/woodpulse
Environment=WOODPULSE_DATA_DIR=/var/lib/woodpulse
Environment=WOODPULSE_CONSOLE_LOG=0
# 用 xinit 起 X 再拉起程序
ExecStart=/usr/bin/startx /usr/bin/env python3 -m woodpulse --fullscreen
Restart=on-failure
RestartSec=5
# 退出时给程序留出收尾时间：停采集、结束批次、释放相机
TimeoutStopSec=25
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now woodpulse
systemctl status woodpulse
journalctl -u woodpulse -f
```

**退出顺序为什么重要**：程序收到 SIGTERM 会走 `shutdown()` ——
中断进行中的批次并封存、停平台客户端、等线程结束、release 相机。
`TimeoutStopSec` 小于 25 秒可能让它被强杀，表现为"上次未正常退出"，
下次启动会把那个批次恢复为中断态（数据保留，但不自动续扫）。
这条路径有专门的验收用例（H14）。

## 6. 现场验收清单

按 PRD §13 的用例逐条走一遍，每条都给出**这一台上**的具体做法：

| 编号 | 在这台机器上怎么做 | 通过标准 |
|---|---|---|
| H01 | `python3 -m woodpulse --headless` 看遥测；同时开 `htop` / `vcgencmd measure_temp` | 数值一致或差异可解释；不可用字段不出现随机值 |
| H02 | 拔网线 → 看状态条变「离线」→ 插回 | 显示时效；速率不出现负值；outbox 里的事件恢复后补传 |
| H03 | 运行中拔掉相机 USB | 相机状态变「重连中 + 原因」；插回后自动恢复；FPS 来自成功读帧计数 |
| H04 | 看「环境与自检」页 | 雷达显示「样例回放」，IMU / 电池 / GPU 显示「未接入」 |
| H05 | 开始 → 暂停 → 继续 → 结束 | 序列图列数按帧推进；暂停期间**不再追加**；结束后不再变化 |
| H06 | 同一轮次做两遍 | 帧内容与结果完全相同；两个批次号不同，无残留标记 |
| H07 | 连续绕柱并反复点「标记位置」 | 保存当前截图与样例帧号；不暂停采集；不显示角度/轨迹/深度 |
| H08 | 用模拟平台的控制台发一条过期命令 | 终端回 `failed` + `command_expired`，状态不变 |
| H09 | 平台下发配置 → 确认 → 重启程序 | 配置版本持续保存；平台收到相同版本 ack |
| H10 | 上传中断网再恢复 | 无重复文件；字节与摘要正确 |
| H11 | 用 `tools/mock_platform.py` 的 `artifact` 命令下发演示包 | 正确包通过；改坏一字节则失败；旧版本保留 |
| H12 | 在更新页点空白处、切页面 | 不产生任何烧录 / VBUS / 摘要通过事件 |
| H13 | 采集中下发更新 | 只暂存；当前批次模型版本不变 |
| H14 | `kill -9` 后重启程序 | 该批次恢复为中断态；数据保留；不自动续扫、不重复上传 |
| H15 | 终端与平台并排看同一批次 | 柱、测区、批次、配置版本、模型版本、datasetHash 一致 |
| H16 | 在屏幕上连续操作一整轮 | 按钮点得到；相机不拉伸；日志默认折叠；没有蓝色旧主题 |

H01/H05/H06/H07/H08/H11/H12/H13/H14/H15/H16 已自动化，直接跑：

```bash
python3 tests/test_acceptance.py
```

## 7. 常见故障

| 现象 | 先查什么 | 处理 |
|---|---|---|
| 界面起不来 | `python3 -c "from PyQt5 import QtCore"` | 装 `python3-pyqt5`；或先用 `--headless` 确认核心层正常 |
| 中文显示成方块 | `fc-list :lang=zh` | `sudo apt install fonts-noto-cjk` |
| 相机一直「未接入」 | `ls /dev/video*`、`v4l2-ctl --list-devices` | 改配置里的 `camera.device`；确认没被别的进程占用 |
| 相机能打开但帧率很低 | 设备状态页看「采集 FPS」与「丢帧」 | 工业相机常用 MJPG；确认线材与供电；必要时降分辨率 |
| 平台一直离线 | `python3 -m woodpulse --check` 的「平台可达性」 | 核对 `platform_url` 与令牌；防火墙放行端口 |
| 平台显示离线但终端在线 | 状态条是否在跳；`journalctl -u woodpulse` | WebSocket 被中间设备掐断时会这样；看重连日志与心跳间隔 |
| 上传卡在某个文件 | 数据交付页看「上传状态」列 | 看日志里的失败原因；退避后会自动重试，不会无限空转 |
| 重启后提示恢复了中断批次 | 工作台「更新与恢复」 | 这是设计行为（H14）；确认数据完整后到交付页上传 |
| SoC 温度显示未接入 | `which vcgencmd` | 非树莓派或缺少 `libraspberrypi-bin`；程序不会填估计值 |

日志：`/var/lib/woodpulse/logs/woodpulse.log`（2MB × 3 份轮转），
界面底部「日志」按钮展开最近 400 行。
「设备状态」页的「查看诊断包」会生成一份 JSON，含状态快照、最近日志、
批次列表与命令回执，现场排障直接把它发回来即可。

## 8. 数据与维护

```
/var/lib/woodpulse/
  config.json                运行时配置
  woodpulse.db               本地库（WAL）：批次、文件索引、outbox、命令回执、版本
  batches/<batchId>/         每个批次的完整产物（manifest 原子提交后允许上传）
  staging/                   更新包暂存与解包目录
  logs/                      轮转日志与诊断包
  outbox/                    预留（outbox 目前落在 SQLite 里）
```

- **备份**：直接复制 `woodpulse.db*`（含 WAL）与 `batches/`。
  正在采集时不要只复制 .db 而漏掉 -wal，会丢最近的事务。
- **清理**：交付并确认平台接收后，可以删 `batches/<batchId>/`，
  但库里那条记录留着以便追溯；删目录前先在交付页确认「平台回执：完整接收」。
- **磁盘告警**：自检里低于 2GB 报「注意」、低于 300MB 报「故障」并阻断启动。

## 9. 开发机上做界面核对

没有实机时，可以按真实 800×480 把每页渲染成 PNG 逐页核对：

```bash
pip install PyQt5                       # 开发机
python tools/ui_shots.py --font C:/Windows/Fonts/msyh.ttc --out .cache/shots
```

无头环境常常没有中文字体，渲染出来中文会变方块 —— 所以 `--font` 用来指一个字体文件。
`docs/shots/` 里已经放了各页的渲染快照，可在提交前对照。
